# Сайт FortLite Capital

Исходный код сайта fortlitecapital.ru. Сайт статический: React + Vite, без сервера и базы данных.

После каждого изменения в ветке `main` GitHub сам собирает сайт, проверяет его тестами и выкладывает на хостинг. Отдельно загружать файлы на хостинг не нужно.

---

## Как устроена выкладка

```
правка в GitHub → GitHub Actions: сборка и тесты → загрузка по FTP на хостинг → сайт обновлён
```

Обычно весь путь занимает 1–3 минуты. Ход выкладки виден на вкладке **Actions** репозитория. Если сборка или тесты не прошли, на хостинг ничего не загружается и на сайте остаётся прежняя версия.

## Первоначальная настройка (один раз)

### 1. Хостинг

Подойдёт любой хостинг с FTP: Beget, Timeweb, REG.RU и другие. Из соображений 152-ФЗ лучше хостинг с серверами в России.

1. Привяжите домен к хостингу в его панели управления.
2. Включите бесплатный SSL-сертификат (Let's Encrypt), обычно это одна кнопка в панели.
3. Узнайте или создайте FTP-доступ: адрес сервера, логин, пароль.
4. Узнайте папку сайта на сервере. Например, у Beget это `fortlitecapital.ru/public_html/`.

### 2. Доступы в GitHub

В репозитории откройте **Settings → Secrets and variables → Actions**.

На вкладке **Secrets** создайте три секрета. Их значения не видны никому, даже администраторам:

| Имя | Что вписать |
|---|---|
| `FTP_SERVER` | адрес FTP-сервера, например `fortlite.beget.tech` |
| `FTP_USERNAME` | логин FTP |
| `FTP_PASSWORD` | пароль FTP |

На вкладке **Variables** создайте переменные:

| Имя | Значение | Обязательно |
|---|---|---|
| `FTP_REMOTE_DIR` | папка сайта на сервере, со слешем на конце, например `fortlitecapital.ru/public_html/` | да |
| `DEPLOY_ENABLED` | `true` | да, включает выкладку |
| `FTP_PROTOCOL` | `ftps` (по умолчанию) или `ftp`, если хостинг не поддерживает защищённое соединение | нет |
| `FTP_PORT` | порт, по умолчанию `21` | нет |

### 3. Первая выкладка

Откройте **Actions → «Сборка и выкладка сайта» → Run workflow**. После зелёной галочки сайт откроется на домене.

Если файлы оказались не в той папке, поправьте `FTP_REMOTE_DIR` и запустите выкладку ещё раз.

## Как вносить изменения

**Через сайт GitHub, без программ.** Откройте нужный файл, нажмите карандаш (Edit), исправьте текст и нажмите **Commit changes** в ветку `main`. Через пару минут правка будет на сайте.

Где что лежит:

| Что меняем | Файл |
|---|---|
| Тексты главной страницы, вопросы и ответы | `src/App.jsx` |
| Политика, согласие, реквизиты и другие документы | `src/legal-content.mjs` |
| Телефон, Telegram, почта, адрес | `src/site.mjs` |
| Реквизиты юрлица | `src/entity.mjs` |
| Подвал | `src/SiteFooter.jsx` |
| Цвета, отступы, оформление | `src/unified.css` |
| Картинки, шрифты, иконки | `public/` |
| Заголовок страницы и описание для поиска | `index.html` |

**На своём компьютере.** Нужен Node.js 20 или новее.

```bash
npm install
npm run dev      # просмотр с автообновлением: http://localhost:5173
npm test         # тесты
npm run build    # сборка в dist/client
```

После `git push` в `main` сайт обновится сам.

## Перед публичным запуском

- Сайт сейчас **закрыт от поисковиков**: в `index.html` стоит `<meta name="robots" content="noindex,nofollow">`. Удалите эту строку, когда сайт будет готов к индексации.
- Когда заработает SSL, включите перенаправление на HTTPS в `public/.htaccess`: уберите `#` в двух строках.
- `public/.htaccess` рассчитан на Apache. Для nginx есть пример настройки в `deployment/nginx.conf.example`. Главное в нём — `try_files $uri $uri/ /index.html;`, без этого не откроются страницы документов.

## Если что-то пошло не так

- **Красный крестик в Actions.** Откройте запуск и посмотрите шаг с ошибкой. «Сборка и проверка» означает ошибку в коде после правки. «Выкладка на хостинг» означает неверные доступы, папку или протокол.
- **Откатить правку.** На странице коммита выберите **Revert**. Прежняя версия выложится автоматически.
- **Сайт не обновился, хотя Actions зелёный.** Проверьте `FTP_REMOTE_DIR` и обновите страницу без кеша: Ctrl+F5 или Cmd+Shift+R.
